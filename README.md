# Reproducibility package — *How Reliable and Valid Is an LLM Technology-Evaluation Judge? A Retrospective Measurement Audit Against Ex-Post Outcomes of Korean SMEs*

Public repository: [REPOSITORY-URL]

This repository regenerates Tables I, V-1, V-1b, V-2, V-3 and V-4 of the paper together with the
operating-point, sector-stratified, paired-comparison and triage tables — AUROC plateaus with
bootstrap / DeLong confidence intervals, pairwise DeLong and TOST equivalence tests, test–retest
ICC(1) / ICC(1,k) with exact F-distribution and cluster-bootstrap intervals, operating points with
base-rate re-weighting, sector-stratified AUROC, the cross-validated two-sided triage screen and the
coarse A/B/C screener (the reliability table is printed under the heading `Table V-4`) — on

1. a **synthetic dataset** that is generated here from a seeded, fully documented statistical model
   calibrated to the paper (Table I composition, tier failure rates, sector heterogeneity, the five
   backbones' score distributions and inter-correlations, the within-tier validity ceiling, the
   expert-grade ordinal, the reliability structure, the screener), and
2. the **de-identified real extract**, if obtained from the authors (schema in `SCHEMA.md`), with the
   *same scripts and no code change*.

The Appendix G sensitivity analyses (G-4, G-7, G-8, G-9) are **not** regenerated by a run on the shipped
synthetic data: they need the proprietary description text or a fresh scoring run. They are scripted
against the de-identified extract, so they run with the same scripts once the extract (and, for the
prompt-robustness checks, a scoring run with `scoring/score_openrouter.py`) is in place.

It also ships the **exact LLM scoring client and prompts** so that new descriptions can be scored under
the paper's protocol (temperature 0, seed 42, `max_tokens` 400, reasoning disabled).

> **Data statement.** The analysis uses records of firms evaluated by a Korean public technology-credit
> institution between 2018 and 2023, linked to registry operating status as of end-June 2023; the extract
> carries no per-firm evaluation date. The linked dataset is proprietary and cannot be redistributed. This
> repository contains **no real firm, no description text, no real score and no
> API key**. The synthetic data reproduce the *statistical structure* of the real data — tier shares,
> tier-specific failure rates, sector heterogeneity, score distributions, the dependence between predictors,
> the reliability structure — but **not the text**, and they are not the paper's numbers. A de-identified
> extract sufficient to reproduce the reported analyses is available from the authors on reasonable request,
> subject to the institution's approval. `tools/build_extract.py` documents how that extract is derived.

## Install

```bash
python -m venv .venv && source .venv/bin/activate      # python >= 3.11
pip install -r requirements.txt                        # lower bounds
# or, to match the environment that produced EXPECTED_OUTPUT.md exactly (python 3.12.4):

                                                       # scikit-learn 1.8.0, matplotlib 3.11.0
python analysis/test_metrics.py                        # 12 unit tests, incl. fast DeLong == brute force
```

## (a) Generate the synthetic data

```bash
python synthetic/make_synthetic.py --seed 42 --out data/synthetic
```

Writes `firms.csv` (9,926 firms), `reliability.csv` (139 firms × 12 re-scorings), `screener.csv` (230 firms) and
`generation_report.json` (all calibrated loadings and achieved statistics). Runs in about two seconds. The
generator calibrates its loadings numerically for the requested seed, so the headline targets are hit for
any seed up to sampling noise; the generative model and every constant are documented in the script's docstring.
Options: `--beta` (logit slope of latent risk), `--sector-sd` (sector heterogeneity), `--n-sectors`,
`--llm-sector-bias-sd` (risk-unrelated sector shifts in the LLM score).

## (b) Run the full analysis on the synthetic data

```bash
python analysis/reproduce.py --data data/synthetic --out data/synthetic/output
```

Prints and writes `tables.md` / `results.json` (about 20 s; well under three minutes) and two figures
(`fig_roc_below_A.png`, `fig_reliability_spans.png`). The output for seed 42 is reproduced in
`EXPECTED_OUTPUT.md`. Bootstrap settings follow the paper (2,000 resamples, seed 0, percentile 2.5/97.5;
paired bootstrap 4,000 for TOST; StratifiedKFold(5, shuffle, random_state=42) for the triage CV) and can be
changed with `--n-boot`, `--tost-boot`, `--seed`, `--cv-seed`, `--triage-*`.

## (c) Run the same analysis on the de-identified real extract

Obtain the extract from the authors (see the data statement), place the three files in `data/private/extract/`
(git-ignored) and run

```bash
python analysis/reproduce.py --data data/private/extract --out data/private/output
```

The scripts are schema-driven (`SCHEMA.md`); nothing in them is specific to the synthetic data. Tables I,
V-1, V-1b, V-2, V-3, V-4 and the operating-point, sector-stratified, paired-comparison and triage tables
then reproduce the manuscript's numbers (the supplement table appears only if LLM scores exist outside the
frozen set). The Appendix G sensitivity analyses (G-4, G-7, G-8, G-9) additionally require the proprietary
description text or a fresh scoring run.

## (d) Re-score descriptions with the exact LLM protocol

```bash
cp scoring/.env.example .env            # put your OpenRouter key in .env (git-ignored) — or export OPENROUTER_API_KEY
python scoring/score_openrouter.py --input my_descriptions.csv --out scores.jsonl          # blind_direct_v1, T=0, seed 42
python scoring/score_openrouter.py --input my_descriptions.csv --out enhanced.jsonl --prompt enhanced_v1
python scoring/score_openrouter.py --input my_descriptions.csv --out rel_hot.jsonl --temperature 0.7 --reps 10 --no-seed
python scoring/score_openrouter.py --input my_descriptions.csv --out rel_cold.jsonl --temperature 0 --reps 2
python scoring/score_openrouter.py --to-csv scores.jsonl scores.csv
```

`my_descriptions.csv` needs the columns `id, description`; nothing else is sent. The client reproduces the paper's
request body exactly — `{"model": "anthropic/claude-sonnet-4.6", "messages": [system, user], "temperature": 0,
"max_tokens": 400, "seed": 42, "reasoning": {"enabled": false}}` — parses the first `{...}` block of the reply
(code fences stripped) and records `float(prob_fail)`; unparsable replies are kept with an `error` field and
excluded from analysis. Output is a resumable `.jsonl` (one record per call; `(id, temperature, rep)` already
present are skipped), with at most 6 concurrent requests and 4 retries with back-off. Other backbones:
`--model openai/gpt-5.5`, `qwen/qwen3.5-27b`, `deepseek/deepseek-v4-flash`, `meta-llama/llama-4-maverick`
(Table E-1 of the manuscript). To assemble a `firms.csv` from your own scores, follow `SCHEMA.md`.

## What the synthetic run shows (seed 42)

The synthetic corpus is built so that a method-invariant plateau exists by construction: Sonnet 0.597,
GPT-5.5 0.600 and Qwen 3.5 0.600 on the Below-A frozen set (0.589 within the B-tier for Sonnet), TF-IDF 0.608,
the expert grade 0.614 (0.572 within the B-tier), length-only 0.524; on the full labeled population the
expert grade reaches 0.657 (0.635 Below-A); ICC(1) = 0.986 at temperature 0.7 and 0.995 at temperature 0 with
58% / 95% byte-identical re-scorings; screener AUROCs 0.680 / 0.636 (bare) and 0.713 / 0.708 (anchor).
`EXPECTED_OUTPUT.md` lists each table the pipeline produces. One structural difference from the real data is
deliberate and documented in `synthetic/make_synthetic.py`: LLM scores exist for all firms, whereas the real
extract carries them only on the frozen set and the reliability sample — which is what enables the
population-level supplement table.

## Reproducibility notes

* Every random draw uses `numpy.random.default_rng(seed)`; the generator, the bootstrap and the CV all take
  explicit seeds. AUROC is computed with average ranks and equals `sklearn.metrics.roc_auc_score`.
* `analysis/metrics.py` has no dependency beyond numpy/scipy (+ scikit-learn for the CV splitter); the fast
  DeLong implementation (Sun & Xu 2014) is unit-tested against the O(mn) definition.
* The ICC model is the one-way random-effects model (repeated scorings of the same description are
  exchangeable); we report ICC(1) for a single rating and ICC(1,k) for the mean of k ratings, with exact
  F-distribution intervals (McGraw & Wong 1996) and firm-level cluster-bootstrap intervals.
* Nothing in this repository can regenerate the proprietary text. Runs of `scoring/score_openrouter.py` on
  real descriptions produce files that are git-ignored by default (`scoring/*.jsonl`, `scoring/*.csv`).
